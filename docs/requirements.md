# Traceability persyaratan PRD §7

Status memakai label PRD §4: **planned** (belum dikerjakan), **experimental** (ada implementasi, bukti belum lengkap), **verified** (bukti uji otomatis tersedia di repo). Bukti dihasilkan oleh `cargo xtask test` / `cargo xtask soak` (lihat `docs/testing.md`) dan disalin ke `docs/evidence/`.

| ID | P | Persyaratan (ringkas) | Status | Bukti / catatan |
|---|---|---|---|---|
| K01 | P0 | Boot UEFI ke init di QEMU; 100 cold boot berturut-turut tanpa panic | **verified** | `xtask soak --boots 100` → `docs/evidence/soak-summary.txt` (100/100 pada build tahap 5 lengkap termasuk storage, compute dan inferensi di setiap boot; rata-rata 15,0 s per boot di TCG, dan setiap log memuat `ALL TESTS PASSED (54/54, 0 skipped)`); skenario `acceptance` (marker `[init] Space OS init running`); diagnosis panic diuji oleh skenario `panic-diagnosis`, `kernel-fault-diagnosis`, `kernel-stack-overflow-diagnosis` |
| K02 | P0 | User-space, syscall, IPC, timer, isolasi; akses terlarang mematikan proses uji, bukan kernel | **verified** | `init` menjalankan: tulis ke memori kernel, baca NULL, eksekusi stack NX, lompat ke alamat kernel/non-kanonik, `div`, `ud2`, `cli`, `int3`, TF+`syscall` → proses dibunuh dengan alasan yang benar, kernel lanjut; `syscall` dengan `rsp` bermusuhan kembali normal; ELF rusak ditolak; 49 uji negatif ABI (`bin/abi_negative`); IPC echo + transfer handle; `sleep(50 ms)`; proses runaway di-preempt dan di-kill |
| K03 | P0 | Kuota dan reclamation; siklus berulang tanpa kebocoran yang terus tumbuh | **verified** | `bin/quota`: `mem_map` ditolak `Quota` tepat pada batas dan dapat dipakai ulang; 50 siklus spawn/exit `bin/worker`, 20 siklus kill-saat-blocking `bin/ipc_echo`, dan 3 × 20 siklus kill saat `sleep`/`recv`/`wait` (`bin/blocker`) → jumlah frame bebas dan heap kernel identik sebelum/sesudah |
| D01 | P0 | VirtIO block dan VFS; baca model dari disk guest, verifikasi checksum setelah reboot | **verified** | Driver virtio-blk 1.0 (PCI modern, polling) + FAT32 read-only + `SYS_FS_OPEN/READ/STAT` di balik hak root `FS`; `init` menghitung SHA-256 di guest (implementasi sendiri, lebih dulu diuji terhadap vektor FIPS) dan mencocokkannya dengan manifest yang dibuat host; skenario `storage-reboot` menuntut verifikasi lulus pada dua boot berturut-turut; matriks `compat` menambahkan perangkat transisional, antrean 4 deskriptor, dan mesin tanpa disk sama sekali. **Volume data juga bisa ditulis** (ADR-0015): `SYS_FS_CREATE`/`SYS_FS_WRITE` di balik hak root `FS_WRITE` yang terpisah dari `FS`, berkas ditulis lalu dibaca ulang byte demi byte, dan skenario `storage-reboot` menuntut boot kedua menemukan penghitung yang ditinggalkan boot pertama. ESP tempat boot tidak bisa dijangkau: ia bukan perangkat virtio. ADR-0007, ADR-0010, ADR-0015 |
| C01 | P0 | Compute ABI CPU: versi, invalid handle, batas buffer, unsupported op, timeout, cancel | **verified** | Objek memori bersama di kernel (`SYS_VMO_*`) + layanan user-space `bin/spacecompute` (ABI v0, backend CPU). Uji kontrak di `init`: HELLO sebelum permintaan lain, versi salah ditolak, device query, buffer bersama, batas buffer (`BadHandle`/`Invalid`/`MsgSize`), operasi tak didukung (`NoSys`), timeout lalu dilanjutkan, cancel, dan tiga siklus layanan tanpa kebocoran frame. ADR-0008 |
| A01 | P0 | Model kecil menghasilkan 128 token offline sesuai baseline | **verified (dengan catatan model)** | `bin/spaceai` memuat SpaceLM v0 dari disk guest, memverifikasi SHA-256 terhadap manifest, menolak tiga model rusak, lalu menghasilkan 128 token lewat Compute ABI. Semua token **identik** dengan baseline yang dipatok implementasi referensi host (math dan tata letak dipakai bersama). Metrik dilaporkan: TTFT, token/detik, working set, RSS runtime. **Catatan jujur:** model referensi 115 ribu parameter dan **tidak dilatih**, bukan 100–500 juta parameter seperti saran PRD §6; yang dibuktikan adalah kebenaran pipeline native, bukan kualitas keluaran. ADR-0009 |
| L01–L03 | P1 | SpaceLink indeks, revokasi, context bundle | **verified (kontrak), peringkat sederhana** | `bin/spacelink` mengindeks korpus `/spaceos/docs`, memberi peringkat chunk, mencabut dokumen, dan menyusun context bundle di bawah anggaran byte. Setiap chunk membawa path, rentang byte dan SHA-256 sehingga `init` memverifikasi provenance-nya sendiri dengan membaca ulang berkas. Revokasi menghapus dokumen dari kueri maupun bundle **dan** bertahan melewati indeks ulang. Digest bundle dapat direproduksi dan dihitung ulang oleh pemanggil. **Catatan jujur:** peringkat leksikal (hitung kemunculan istilah), bukan embedding; indeks dan daftar revokasi masih hanya di memori — volume data sudah bisa ditulis (ADR-0015), tetapi SpaceLink belum dipindahkan ke sana, jadi revokasi bertahan melewati indeks ulang dan belum melewati reboot; repo SpaceLink dari PRD §10 tetap tidak tersedia, jadi yang dibuktikan adalah kontraknya, bukan mesin retrieval-nya. ADR-0013 |
| G01 | P1 | Agent membaca/patch/uji dalam workspace; keluar scope ditolak | **verified (dengan catatan tulis)** | `bin/spaceagent` lahir hanya dengan satu channel ke `bin/spacebroker`; `fs_open` miliknya ditolak kernel. Broker memegang satu-satunya kapabilitas file (dipersempit ke `FS`), memeriksa setiap path terhadap workspace `/spaceos/ws` komponen-per-komponen, dan mencatat setiap panggilan — diizinkan maupun ditolak — di audit log operator. Uji membuktikan siklus baca → tambal → check lulus, dan delapan bentuk jalan keluar ditolak. **Catatan jujur:** tambalan masih mendarat di overlay dalam memori. Alasannya bukan lagi volume read-only — volume data sudah bisa ditulis sejak ADR-0015 — melainkan broker belum dipindahkan ke sana; dan "uji" berarti satu check bawaan, bukan runner uji umum. ADR-0012 |
| I01 | P1 | Satu adapter cloud lulus auth/streaming/tool use/timeout/cost cap | **blocked** | Memerlukan tiga hal yang belum ada, berurutan: driver virtio-net, stack TCP/IP, dan TLS. TLS tidak akan ditulis sendiri di sini (lihat ADR-0014 untuk alasan yang sama pada kripto paket). Tanpa ketiganya tidak ada bagian I01 yang bisa diuji secara jujur — auth, streaming, timeout dan cost cap semuanya diukur terhadap endpoint sungguhan |
| U01 | P1 | Desktop/terminal/file manager/Stop tetap hidup saat worker inferensi crash | **verified untuk terminal/file manager/Stop; desktop grafis belum ada** | `bin/spaceshell` memiliki sesi konsol, daftar berkas (`SYS_FS_LIST`) dan masa hidup worker; loopnya tidak pernah memblokir pada worker (`recv` non-blocking + `SYS_WAIT` bendera `NONBLOCK`). Uji menjalankan empat worker berturut-turut — crash (`PAGE_FAULT`), macet tanpa syscall, tidur, dan selesai normal — dan menuntut sesi tetap menjawab `STATUS` serta membuka daftar berkas setiap kali, `STOP` berhasil pada worker macet maupun yang tidur. Sesi hanya memegang `SPAWN|FS` hasil penyempitan handle root. Skenario `terminal` mem-boot image yang sama dengan `init=bin/spaceterm` dan **mengetik** `help`, `status`, `ls /spaceos`, `run hang`, `status`, `stop`, `status`, `quit` lewat COM2 — jadi Stop yang menghentikan worker macet benar-benar datang dari ketikan. Masukan konsol (keyboard IRQ1 dan COM2 IRQ3) sampai ke user space lewat `SYS_CONSOLE_READ` di balik hak root `CONSOLE` yang terpisah. Jalur keyboard diuji tanpa perlu ada orang: `debug_op::PS2_INJECT` menyuruh controller 8042 mengirim satu tombol, dan uji menuntut byte itu sampai ke `console_read` — jadi IRQ 1 terbukti hidup di kesembilan mesin `compat`, bukan hanya di dua skenario yang diketik. Byte yang hilang karena ring penuh dilaporkan sebagai `DataLoss` **sebelum** byte yang selamat diserahkan, sekali per episode; uji meluapkan ring dengan sengaja (`debug_op::CONSOLE_FLOOD`) dan menuntut laporan itu datang lebih dulu, lalu sesi membuang baris yang setengah jadi alih-alih menjalankannya. **Catatan jujur:** "desktop" berarti konsol teks framebuffer — belum ada window manager atau GUI, tidak ada riwayat perintah, dan peta keyboard hanya set 1 tata letak US. ADR-0011 |
| P01 | P1 | Paket bertanda tangan dan rollback | **verified (MAC, bukan kunci publik)** | Format paket `spaceabi::pkg`: header menandatangani nama, versi, panjang dan SHA-256 payload dengan HMAC-SHA256; verifikasi berurutan bentuk → autentikasi → isi dan menyebut alasan penolakan. `bin/spacepkg` memasang, menolak paket yang dirusak/dipalsukan/dipotong tanpa mengubah apa pun, dan `ROLLBACK` mengembalikan payload versi sebelumnya byte demi byte. HMAC diuji terhadap vektor RFC 4231 di dalam guest. **Catatan jujur:** ini MAC simetris — kunci rilis ada di dalam image, jadi yang diberikan adalah integritas dan autentisitas terhadap pihak tanpa kunci, **bukan** distribusi tepercaya; store masih di memori: volume data sudah bisa ditulis (ADR-0015), tetapi `spacepkg` belum dipindahkan ke sana, jadi rollback terbukti sebagai logika dan belum sebagai instalasi yang bertahan reboot. ADR-0014 |
| H01 | P2 | PC/GPU referensi | **blocked** | Tidak ada perangkat keras fisik di lingkungan ini; semua bukti berasal dari QEMU/TCG. Yang bisa dikerjakan tanpa perangkat keras sudah dikerjakan: linear map tidak lagi meng-alias MMIO (ADR-0010), dan matriks `compat` menutup sembilan konfigurasi mesin virtual. Tahap 6 PRD ("studi kelayakan, driver") dijawab sebatas studinya: `docs/gpu-feasibility.md` menyebut kapabilitas perangkat yang harus ada lebih dulu dan mengapa driver GPU tidak ditulis tanpa perangkat untuk memverifikasinya |
| H02 | P2 | ARM64 boot/isolasi/inferensi CPU virtual | planned | Batas modul `kernel/src/arch/` disiapkan (ADR-0001), tetapi isinya x86-64 sepenuhnya: GDT/IDT, `syscall`/`sysret`, PIC/PIT. Port aarch64 berarti boot EL1, tabel translasi, vektor eksepsi, GIC dan timer generik, lalu mengulang K01–K03 pada profil QEMU `virt` + AAVMF. Belum dimulai |

## Kompatibilitas (PRD §6 "berjalan pada profil yang didukung")

Bukan persyaratan bernomor, tetapi syarat agar klaim di atas berarti di luar satu
profil. `cargo xtask compat` mem-boot image yang sama pada sembilan konfigurasi
QEMU (ADR-0010); hasil sesi ini ada di `docs/evidence/compat-summary.txt`. Mesin
tanpa perangkat keras yang dibutuhkan melewati uji terkait dan mencatatnya sebagai
*skipped*, sehingga hitungan lulus tidak pernah membesar karena uji yang tidak
dijalankan. Perangkat keras fisik tetap di luar cakupan (H01/H02).

## Pemetaan uji → persyaratan

`user/init/src/main.rs` memberi label setiap uji dengan ID persyaratan; ringkasan lulus/gagal dicetak sebagai `[init] PASS <ID>: …` / `[init] FAIL <ID>: …` dan kemudian `[init] ALL TESTS PASSED (n/n)` atau `[init] TESTS FAILED`. Harness membaca marker ini dan kode keluar QEMU.
